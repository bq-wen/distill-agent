# 技术栈面试要点（求职版）

> 面试前必读。分三层：**深挖区**（必问，要能讲原理+权衡）、**广度和加分区**（建议做进项目，每个都是独立故事）、**了解区**（提到不深讲）。每块附高频问题。

## 0. 先想清楚你的叙事主线

面试官不会按文档逐条问，你要有**一条主线**把技术栈串起来：

> **"我用自研图运行时做了通用数字分身模板：蒸馏流水线把资料加工成知识库，在线分身只读检索回答。技术栈围绕两个矛盾展开——可控性（工具治理）和容量（单机演示 vs 扩展路径）。"**

每个技术点都挂在这条主线上回答，而不是孤立背八股。

## 1. 🔴 深挖区（必问，讲原理 + 权衡）

### 1.1 RAG 全链路（最高频）
项目位置：`knowledge/`（chunking/embedding/retrieval）+ `application/tools.py`

要能讲：
- **混合检索为什么**：向量（语义）找同义表达，FTS5（关键词）锁专有名词；单一方案各有盲区
- **chunk 怎么切**：按 Markdown 标题分块，块内语义完整 + 保留 heading 上下文；讲出"太大稀释、太小断义"的权衡
- **embedding 选型**：bge-small-zh 中文好、体积小、CPU 可跑；对比 OpenAI embedding（要联网/花钱）
- **阈值 0.35**：低于阈值视为未命中 → "没资料时明确说不知道"是产品信任设计
- **评估缺失 → 增强点**：主动说"我还没做检索评估集，计划用 20-30 条 QA 跑 recall@k"，比被问到才说强

高频问题：RAG 和微调的区别？检索不到怎么办？为什么不用向量数据库？怎么调 chunk 大小？

### 1.2 Agent 架构与工具治理（你的差异化）
项目位置：`application/graph.py`、`wengraph_runtime.py`、vendor 的 `tools/policy.py`

要能讲：
- **ReAct 循环**：LLM 推理 → 决定调工具还是回答 → 工具结果回注 → 再推理
- **治理三层**：CapabilityPolicy（谁能用）→ RiskPolicy（当前模式能不能真执行）→ ToolGuard（门卫节点）
- **两种模式对比**：UNATTENDED 只读服务 vs SUPERVISED 蒸馏写库强制审批——**同一套机制，两个安全模型**
- **为什么自研不直接用框架**：把安全决策做成图内显式节点，可观测、可测试、可扩展

高频问题：和 LangChain 比有什么不同？工具调用协议怎么设计的？怎么防止 LLM 滥用工具？（答：能力授权收敛到最小可用集）

### 1.3 FastAPI + asyncio 并发模型
项目位置：`api/app.py`、`application/runs.py`

要能讲：
- **202 + 轮询**：提交与结果解耦，慢依赖（LLM 秒级）不占连接
- **有界队列 + 固定 worker**：背压（429）、容量可控
- **提交限流**：按客户端 IP 固定窗口限流（默认 30 次/分，`PERSONAL_AGENT_RATE_LIMIT_PER_MINUTE`），防无登录接口被滥用；内存实现，随单进程扩展路径一起迁移
- **单进程约束**：队列进程内结构 → 扩展路径 Redis/Celery（README 明示）——主动讲"我知道瓶颈在哪、怎么扩"
- **Pydantic 契约**：API 边界字段白名单，响应里绝无内部结构

高频问题：asyncio 和线程的区别？为什么不用 Celery？409 冲突是什么？（同一会话并发提交）

### 1.4 TypeScript + React 工程化
项目位置：`frontend/`（React 18 + TS + Vite + ESLint 全开）

要能讲：hooks 状态管理（messages/pending/error）、轮询实现（pollRun）、sessionStorage 会话隔离、`npm run lint` 零告警（`--max-warnings=0`）、三栏布局（知识面板/对话/来源卡片）、Markdown 部分渲染
增强点：openapi-typescript 从后端契约生成类型（单一事实源）——面试可提

### 1.5 工程化门禁（已实现）
- 后端：`ruff check .`（`ruff.toml`，Python 3.12 目标）——与前端 eslint 对等的 lint 门禁
- 后端测试：`pytest`（45 个，离线可复跑，脚本化模型零外部依赖）
- 前端：`tsc -b`（严格类型）+ `eslint --max-warnings=0` + `vite build`
- CI：GitHub Actions（`.github/workflows/ci.yml`）在 push/PR 时自动跑以上全部

要能讲：为什么给后端也加 lint 门禁（前端有 tsc/eslint，后端类型与风格之前全靠自觉）；为什么不用 ruff format（避免全库格式 churn，lint 先行）

## 4. 高频面试问题速答卡

**"你这个项目最大的技术挑战是什么？"**
> 把安全治理做进图运行时：工具调用不是散装 if-else，而是 Capability/Risk 双策略 + 门卫节点；同一套机制覆盖两种链路（在线只读无人值守 / 蒸馏写库人工审批）。挑战在于把"安全"从横切关注点变成图的显式流程。

**"为什么不用 LangChain？"**
> 可控性 + 学习深度。LangChain 抽象层厚、安全决策外挂；自研能把治理做成图节点，也逼自己理解 ReAct 和工具调用本质。代价是兼容性维护，所以作为固定 submodule 隔离。

**"这个项目能商用吗？"**
> 诚实拆解：单进程队列是容量瓶颈（→ Redis/Celery 路径已想好）；本地 embedding 够小规模；人工审批保证内容质量；要商用还需要评测集、红队测试、观测系统。面试里"知道差距"是加分。

**"你贡献了什么 vs 用现成轮子？"**
> WenGraph 自研（图运行时 + 治理框架）；应用层原创：混合检索、异步队列、安全引用合同、蒸馏流水线设计。检索模型用现成的（bge）——选型也是工程决策。

## 5. 建议的面试讲述顺序（10 分钟版）

1. **30 秒**：项目一句话 + 架构图（doc/architecture.md 第 6 节开场白）
2. **2 分钟**：展示链路走一遍（提问 → 队列 → ReAct → 检索 → 引用）
3. **2 分钟**：治理模型（两种模式对比表）
4. **2 分钟**：蒸馏流水线（节点 + 人工审批 + 溯源）
5. **2 分钟**：容量与扩展（单进程约束 → Redis/Celery 路径）
6. **1 分钟**：诚实列出不足与增强点（评估、流式、红队）
